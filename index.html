1F 查核大廳（1F 原教學查核結果）

逐項對照 Notion、Gemini CLI、OpenAI Codex、Claude Code 官方文件。方法可以用，但要更新成 2026 年的做法。（4 ✅ 正確，可保留 ｜ 5 ⚠️ 可以用，但要修正 ｜ 1 ❌ 說法錯誤）

1. [停更] 本機伺服器的維護狀態 ❌

原文：這是比較好的新方法

官方 README 已標示不再積極維護，主推遠端 Notion MCP（OAuth），repo 未來可能停用。

2. [限定] 誰能建立整合 ⚠️

原文：照步驟人人都能做

只有工作區擁有者能建立內部整合；學校老師多半要請管理者建立。

3. [語法] gemini mcp add ⚠️

原文：gemini mcp add notion -e ... -- npx ...

選項放名稱前；預設寫入「專案」設定，要加 -s user 才是全域。

4. [資安] 權杖明碼 ⚠️

原文：把 ntn_ 直接寫進 settings.json

三種 CLI 都能引用環境變數，設定檔只留變數名稱。

5. [改名] 介面名稱 ⚠️

原文：Integration / Access → Edit access

Notion 正改名為 Connection；後台分頁叫 Content access。

6. [誇大] 「毫秒級」速度 ⚠️

原文：遠端一定卡、本機一定毫秒級

體感描述；npx 首次要下載套件反而較慢。改說「少一層中繼、不用重登」。

7. [正確] ntn_ 與 secret_ ✅

2024 年 9 月起新權杖為 ntn_，舊的 secret_ 仍可用。

8. [正確] Windows 寫法、開門步驟、工具數 ✅

npx.cmd／cmd /c 正確；頁面 Connections 正確；v2.0 起 22 個工具。

2F 兩扇門：先選路線

遠端 OAuth 是官方主推；本機權杖控制範圍更細。

🚪 A 遠端 OAuth

  • ✅ 官方主推、持續維護
  • 瀏覽器登入，可能要重登
  • 看得見你本人能看的頁面
  • 不用 Node.js、人人可設

🔑 B 本機權杖

  • ⚠️ 已不再積極維護
  • ntn_ 權杖不過期
  • 只看得見邀請過的頁面
  • 要 Node.js + 擁有者身分

3F 打一張門禁卡（路線 B）

建立內部整合 4 步驟與從零到能用標準順序：安裝 Node.js → 建立內部整合 → 複製 ntn_ 權杖 → 頁面 Add connections → 設定 NOTION_TOKEN → CLI 加入 notion → /mcp 測試

Step 1 開後台

前往 Notion Integrations 後台（Developer portal 的 Internal connections）。

Step 2 建立整合

New integration／Create a new connection：取名「AI CLI 小幫手」、選工作區、類型 Internal。

Step 3 複製權杖

Configuration 分頁 → Internal Integration Secret → Show → Copy。

Step 4 勾權限

Capabilities：勾選 Read／Update／Insert content；使用者資訊選「不含 email」→ Save。

🔐 權杖＝備用鑰匙：不要貼到公開地方、不要放進 Git、不要出現在截圖裡

4F 卡開房門

新建的整合預設看不到任何頁面，九成的「找不到頁面」都是忘了這一步。

方法 A: 在頁面裡

母頁面右上 ••• →（新版在 More 底下）Connections → Add connections → 搜尋小幫手 → Confirm。

方法 B: 在後台

整合設定頁 → Content access 分頁（舊版叫 Access）→ 勾選頁面或資料庫 → Save。

繼承規則

  • 授權母頁面，子頁面自動繼承
  • 新的頂層頁面要再開一次
  • 建在已授權頁面底下的不用

5F 鑰匙放進環境變數

不要把權杖寫死在設定檔。放進 NOTION_TOKEN，三台 CLI 都能共用，換卡時只改這裡。

【Mac／Linux】分頁（ZSH）
# 寫進 ~/.zshrc，之後每次開終端機都讀得到
echo 'export NOTION_TOKEN="ntn_請換成你的權杖"' >> ~/.zshrc
source ~/.zshrc

# 確認
echo $NOTION_TOKEN
【Windows】分頁（POWERSHELL）
# 寫入使用者環境變數（要重開終端機才生效）
setx NOTION_TOKEN "ntn_請換成你的權杖"

# 重開後確認
echo $env:NOTION_TOKEN

6F 三台電梯：設定產生器與三台速查表

點選下方按鈕切換三台 CLI 指令與設定檔格式：

# 先移除舊設定（全域）
gemini mcp remove -s user notion

# 選項放在名稱前；-s user 寫入全域
gemini mcp add -s user -e NOTION_TOKEN="$NOTION_TOKEN" notion npx -y @notionhq/notion-mcp-server

7F 電梯維修室（8 大症狀診斷 ＆ 出電梯前小考）

先重開 CLI、輸入 /mcp 確認 notion 已連線，再測試：「請用 Notion 工具搜尋我授權的頁面，列出前 5 筆標題。」

1. 找不到頁面 []

原因：頁面沒有 Connect 給整合。
解法：母頁面 ••• → Connections → Add connections，或後台 Content access 勾選。

2. 401 Unauthorized

原因：權杖貼錯、有空白、已 Refresh 失效，或環境變數沒讀到。
解法：終端機 echo $NOTION_TOKEN 確認；重開終端機與 CLI。

3. 403 權限不足

原因：Capabilities 沒勾 Update／Insert。
解法：後台 Configuration 勾選後 Save。

4. spawn npx ENOENT

原因：Windows 的 npx 其實是 npx.cmd。
解法：command 改 npx.cmd，或 cmd /c npx -y ...。

5. Codex 啟動逾時

原因：npx 第一次下載套件超過預設 10 秒。
解法：config.toml 加 startup_timeout_sec = 60。

6. Gemini 一直 DISCONNECTED

原因：本機（stdio）伺服器只在信任的資料夾連線。
解法：在該資料夾執行 gemini trust。

7. Claude Code 名稱格式錯

原因：--env 後面直接接了名稱，被當成另一組 KEY=value。
解法：在 --env 與名稱之間放 --scope user。

8. 叫不到 database 查詢

原因：v2.0 起資料庫改叫 data source，舊工具已移除。
解法：改說「查詢資料來源（data source）」。

🎯 出電梯前的小考（5 題重點解析）

  1. 本機 @notionhq/notion-mcp-server 目前的官方狀態是？ → 不再積極維護，官方主推遠端 MCP（目前仍可使用）。
  2. 誰可以建立 Notion 內部整合？ → 只有工作區擁有者（Workspace Owner）。
  3. gemini mcp add 不加 -s 時，設定會寫到哪？ → 目前資料夾的專案設定（預設 scope 是 project，要加 -s user）。
  4. Codex 想直接轉送系統的 NOTION_TOKEN，要用哪個欄位？ → env_vars = ["NOTION_TOKEN"]。
  5. 權杖設好了，AI 卻說找不到任何頁面，最可能是？ → 忘了在頁面 Add connections（新整合預設看不到任何頁面）。

8F 頂樓：路線 A 與資安

不是工作區擁有者？直接走路線 A，第一次會跳出瀏覽器請你登入 Notion。

REMOTE OAUTH 指令

claude mcp add --transport http --scope user notion [遠端MCP網址: mcp.notion.com/mcp]

🔄 權杖外洩

整合設定頁 Configuration → Refresh，舊權杖立即作廢；更新環境變數即可，三台 CLI 設定不用改。

👥 一卡多用

三台共用一張卡很方便，但寫入都記在同一個整合名下；要分開追蹤就建三個整合。

🏫 學校情境

學生 Chromebook 不能直接跑這些 CLI；本教學適合在老師或網管的 Mac／Windows 上設定。
